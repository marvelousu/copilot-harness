# MCP カタログ

同時に有効化するのは3つまでを目安にする。5つを超えるとツール定義が文脈を圧迫し、VS Code のツール128個上限にも当たる。

## 入れるもの

### github（常時オン）

リポジトリ、Issue、PR、コードレビューを直接操作する。IDE と GitHub の往復が消えるので、導入効果が最も大きい。リモート型で OAuth 認証、ローカルに何も入れなくていい。

自社が GitHub Enterprise Server の場合は URL が変わる。管理者に確認する。

### context7（常時オン）

ライブラリとフレームワークの最新ドキュメントを取得する。学習データが古くて API が変わっている場合の誤りを潰せる。API キー不要。

送信されるのはライブラリ名とクエリで、自社コードではない。それでも外部送信ではあるので、規定の確認対象になる。

### playwright（必要時）

実ブラウザを操作する。Web UI の動作確認、E2E テストの作成、スクリーンショット取得に使う。Microsoft 製。

### playwright-ext（必要時）

既存のブラウザセッションに拡張経由で接続する。社内システムなど、ログイン済みの状態が必要な相手に使う。新しいプロファイルを立てないので認証をやり直さずに済む。

### windows-mcp（必要時）

Windows のデスクトップ GUI を操作する。ブラウザ外のネイティブアプリを触る唯一の手段。

Claude の computer-use に相当する組み込み機能は Copilot にはない。デスクトップ操作が要るならこれが代替になる。`uv` が必要。

## 検討に値するもの

| サーバ | 用途 | 入れる条件 |
|---|---|---|
| memory | セッションをまたぐ事実の保存 | Copilot には自動メモリがないため、蓄積が要るなら候補 |
| sentry | 実障害のスタックトレース取得 | Sentry を使っているなら |
| postgres / mysql | スキーマ参照とクエリ検証 | DB を触る作業が多いなら |
| figma | デザインからのコード生成 | Figma が設計の正本なら |
| jira / linear | チケット参照 | 課題管理がそこにあるなら |

DB 系は接続情報を持つので、読み取り専用ユーザーに限定する。

## 入れないもの

自宅環境から持ち込まない。職場で価値がないか、個人の資格情報に紐づいている。

| サーバ | 除外理由 |
|---|---|
| proxmox | 自宅インフラ専用 |
| x_docs / xmcp | 業務と無関係。個人 API キーに紐づく |
| cloudflare 一式 | 個人アカウントの認証が前提 |
| meshy / elevenlabs / pixel | ゲーム制作用のアセット生成 |
| godot-mcp | 業務スタックにない |
| 1Password 連携 | 個人のサービスアカウントに紐づく |

## 有効化の切り替え

VS Code のチャット画面でツールピッカーを開き、サーバ単位でオンオフする。作業フェーズごとに切り替える運用にする。設定ファイルから消す必要はない。
