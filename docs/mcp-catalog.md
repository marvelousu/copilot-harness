# MCP カタログ

同時に有効化するのは3つまでを目安にする。5つを超えるとツール定義が文脈を圧迫し、VS Code のツール128個上限にも当たる。

## 入れるもの

### github（常時オン）

**Copilot に組み込まれていない。** 手動で追加する必要がある。組み込みの GitHub 連携はリポジトリの文脈を読む範囲までで、Issue を立てる、PR を一覧する、リポジトリ情報を引くといった操作は MCP を入れて初めてできる。

認証は Copilot の OAuth をそのまま使うのでトークン設定が不要。ローカルプロセスも立たない。導入コストが最も低い。

各ツールは対応する GitHub 機能と同じ権限要件を継承する。有料機能に対応するツールは同じ契約が必要になる。

自社が GitHub Enterprise Server の場合は URL が変わる。管理者に確認する。

### context7（常時オン）

ライブラリとフレームワークのドキュメントを、そのバージョンに合わせて取得するサーバ。ライブラリ名を渡すと該当するドキュメントを解決して返す。

解決する問題は、モデルの学習データが古くて API が変わっている場合の誤りである。存在しない引数を書く、廃止されたメソッドを呼ぶ、といった失敗が減る。API キーは不要。

送信されるのはライブラリ名とクエリで、自社コードではない。それでも外部送信ではあるので規定の確認対象になる。

### playwright（必要時）

実ブラウザを操作する。Web UI の動作確認、E2E テストの作成、スクリーンショット取得に使う。Microsoft 製。

### playwright-ext（必要時）

既存のブラウザセッションに拡張経由で接続する。社内システムなど、ログイン済みの状態が必要な相手に使う。新しいプロファイルを立てないので認証をやり直さずに済む。

### desktop（必要時）

**これが computer use の MCP である。** `@zavora-ai/computer-use-mcp` を `desktop` という名前で登録している。ウィンドウの列挙と切り替え、要素の検索とクリック、フォーム入力、キー送信、スクリーンショットを提供し、Windows、macOS、Linux で動く。Rust のネイティブモジュールで、`npx` で起動する。

**Copilot CLI で接続、ウィンドウ列挙、VS Code の操作まで実測済み。** MCP プロトコルの 2026-07-28 と旧版の両方を話すので、CLI と VS Code のどちらのクライアントにも繋がる。ツールを約30個追加するので、GUI を触る作業のときだけ有効にする。

windows-mcp（CursorTouch 製）は候補から外した。旧プロトコルしか話せず、Copilot CLI 1.0.83 に接続できない。UI ツリーの取得が強い長所はあるが、CLI で使えない以上、この構成では採らない。VS Code 側のクライアントなら繋がる可能性はあるが未検証。

| サーバ | 状態 |
|---|---|
| zavora-ai/computer-use-mcp | 採用。CLI で実測済み |
| CursorTouch/Windows-MCP | CLI 接続不可。VS Code は未検証 |
| domdomegg/computer-use-mcp | npm にあるが未検証 |

## 検討に値するもの

| サーバ | 用途 | 入れる条件 |
|---|---|---|
| sentry | 実障害のスタックトレース取得 | Sentry を使っているなら |
| postgres / mysql | スキーマ参照とクエリ検証 | DB を触る作業が多いなら |
| figma | デザインからのコード生成 | Figma が設計の正本なら |
| jira / linear | チケット参照 | 課題管理がそこにあるなら |

DB 系は接続情報を持つので、読み取り専用ユーザーに限定する。

## 入れないもの

次のいずれかに当たるサーバは、別の環境で使っていても持ち込まない。

| 判断基準 | 理由 |
|---|---|
| 個人の API キーやサービスアカウントで認証するもの | 共有できず、漏洩時の影響が個人に閉じない |
| 対象の開発スタックにない分野のもの | ツール定義の分だけ毎回の文脈を消費して、使われない |
| 個人環境のインフラを操作するもの | 業務のリポジトリから触る理由がない |
| memory (`@modelcontextprotocol/server-memory`) | Copilot 組み込みの Memory で足りる。リポジトリ単位で各面に共有され、CLI では既定で有効。MCP を足すとツール9個と1タスク1回の呼び出しが増えるだけ |

## 有効化の切り替え

VS Code のチャット画面でツールピッカーを開き、サーバ単位でオンオフする。作業フェーズごとに切り替える運用にする。設定ファイルから消す必要はない。
