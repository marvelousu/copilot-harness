# 記録方針

何をどこに残すか。層は5つで、それぞれ書く人、読まれるタイミング、寿命が違う。

| 層 | 場所 | 書く人 | 読まれるとき | 寿命 |
|---|---|---|---|---|
| 毎回効く規約 | `.github/copilot-instructions.md` | 人 | 全リクエスト | 変更まで |
| 個人の好み | `~/.copilot/copilot-instructions.md` | 人 | 自分の全リクエスト | 変更まで |
| 手順 | `.github/skills/*/SKILL.md` | 人 | 関連するとき | 変更まで |
| 決定 | `docs/decisions.md` | エージェントと人 | 読みに行ったとき | 永続 |
| 自動記憶 | Copilot Memory | Copilot | 各面が自動で | 未使用28日で失効 |

上4つは自分で制御できる。最後の1つは制御できないので、頼りすぎない。

## Copilot Memory に任せる範囲

Copilot Memory は2層ある。リポジトリ単位の事実（規約、構成上の判断、ビルド手順）はそのリポジトリにアクセスできる全員に共有される。個人の好み（コーディングスタイル）は本人だけが、リポジトリをまたいで使う。

読み書きする面は cloud agent、code review、CLI の3つ。VS Code と JetBrains は公式の一覧に無いので、そこで効く前提を置かない。使われなかった記憶は28日で消える。リポジトリの事実は使う前に現在のブランチと照合され、古くなったものは使われない。

**意図的に書き込む手段はない。** 育つに任せる。見る、消すは github.com の Copilot 設定から行い、本人は自分の好みを、リポジトリ所有者はリポジトリの事実を消せる。Business では管理者が個人単位または一括で消せる。

**職場ではまず有効か確認する。** 組織管理のプランでは管理者がポリシーを有効にして初めて動き、その上で個人が opt out できる。無効なら自動記憶は存在せず、残るのは上の4層だけになる。CLI で自分だけ止めるなら `/memory off`。

## 昇格の道筋

1. セッション中に気づいたことは、その場限りでよい。書かない。
2. 同じ訂正を2回したら、行動の規約なら `copilot-instructions.md`、手順なら skill に書く。3回目を待たない。
3. コードから読み取れない判断をしたら、採らなかった案と理由を添えて `docs/decisions.md` に追記する。エージェントは指示ファイルの規約でこれを行う。人が書いてもよい。
4. 自分だけの好みは `~/.copilot/copilot-instructions.md` に置く。チームのリポジトリに入れない。

判断に迷ったら書かない。記録は少ないほど読まれる。

## decisions.md が手狭になったら

`docs/decisions.md` は1ファイルの追記式で、個人が他人のリポジトリで使う分にはこれで足りる。理由の記録が増えて1ファイルで探せなくなったとき、または離任や引き継ぎで知識移転が要るときは、`keep-the-why` に移す。

keep-the-why は SKILL.md 形式の規約で、判断理由をコードと同じリポジトリの `context/` 配下に Markdown で置き、同じコミットで一緒にレビューする。継続記録、既存リポジトリからの遡及復元、担当者への聞き取り、矛盾解消の4モードを持ち、Claude Code と Codex と Copilot で共通に使える。導入は `copilot plugin install keep-the-why@awesome-copilot`。最初の起動で置き場と記録の積極性を聞かれる。

移すときは decisions.md の内容を `context/` へ移し、指示ファイルの追記先を差し替える。両方を並走させない。

## 書かないもの

- コードを読めば分かること。ディレクトリ構成、依存関係、関数の役割。二重管理になって古くなる。
- 一時的な状態。今日どこまでやったか。
- 資格情報、個人情報、社外秘。Copilot Memory は GitHub 側に保存されるので、そこに乗せてはいけないものは会話にも出さない。

## 確認の仕方

- `/memory` で CLI 側の状態を見る。
- github.com の Copilot 設定で記憶の一覧と削除。
- `docs/decisions.md` は PR に含めてレビューを通す。決定がレビューされていない状態を作らない。
- `/env` で読み込まれている指示ファイルと skill を一覧し、意図しない重複が無いか見る。
